## 2026-09-01 - Optimize sigmoid function by replacing numpy with math
**Learning:** Found `numpy.exp` being used in a hot path for scalar operations in `hindsight_api/engine/search/reranking.py`. For single scalar operations, Python's built-in `math.exp` is significantly faster than `numpy.exp` due to avoiding Python-to-C conversion overhead. `numpy.exp` should only be used for vectorized array operations.
**Action:** Replace `numpy.exp` with `math.exp` in single scalar functions like `_sigmoid`. When using `math.exp`, handle `OverflowError` for highly negative values since `numpy.exp` naturally returned 0.0 without raising exceptions, preserving the old behaviour.

## 2026-09-01 - VertexAI Configuration in MemoryEngine
**Learning:** In \`hindsight-api-slim/hindsight_api/engine/memory_engine.py\`, \`MemoryEngine.__init__\` instantiates an \`LLMConfig\` but does not forward the provider-specific configurations (like \`vertexai_project_id\`, \`litellmrouter_config\`, etc.) from the global configuration when falling back to default values. This causes a \`ValueError\` for providers that require them (like VertexAI) when instantiating \`MemoryEngine\` with only the provider name.
**Action:** When creating the \`_default_base_llm\` (and other LLMs) inside \`MemoryEngine.__init__\`, always pass down the provider-specific variables from the global config (e.g. \`config.llm_vertexai_project_id\`).
